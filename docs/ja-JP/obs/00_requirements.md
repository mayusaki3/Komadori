# OBS 連携プロジェクト 要件概要

## 0. 目的
YouTube同時配信とローカル録画を、少ない操作で安全に運用する。OBS本体またはStream Deck相当UIから一括操作し、配信画面にYouTubeコメントと各種オーバーレイを重ねる。

## 1. スコープ
- OBS Studio（v28以降）を前提
- WebSocket制御（外部アプリ連携）
- 配信レイアウト（Webカメラ＋画像・サムネ＋コメント）
- 操作UI（OBS上の簡易パネル／Stream Deck）

## 2. 要件一覧
### R1. 配信と録画の同時実行
- YouTube Live へ配信しながら、ローカルに録画（mkv/mp4選択式）。
- ワンボタンで「配信開始＋録画開始」および停止が可能。

### R2. 操作系
- 操作は次のいずれかから行える。
  - OBS本体の操作パネル
  - Stream Deck（公式プラグイン）または同等のWebパネル
- OBS上に「Stream Deck相当」の簡易ボタンUIを表示できること（ブラウザソース or スクリプトUI）。

### R3. コメント表示
- YouTube Liveのコメントを配信画面に重畳表示。
- 表示/非表示をワンボタン切替。
- 荒らし対策としてNGワード/ユーザーの簡易フィルタ（任意）。

### R4. 画面合成
- Webカメラ映像をベースに、静止画（サムネ）や装飾画像をレイヤーとして重ねる。
- レイヤーのON/OFF、差し替え、位置・サイズのプリセット切替をボタン操作で実行。

## 3. 非機能要件
- **安定性**：配信中のレイアウト切替で落ちないこと。
- **再現性**：シーン／ソース命名規約とテンプレートを用意。
- **操作時間**：開始〜配信安定まで30秒以内を目標。
- **学習コスト**：ドキュメントとボタン名を一致させる。

## 4. 制約
- Windows 10/11 前提。
- OBS WebSocket（同梱）を使用。ポート競合がないこと。
- YouTube API利用時はAPIクォータ制限に留意。

## 5. 成功基準（受け入れ条件）
- ボタン1回で「配信開始＋録画開始」が安定動作。
- コメントが数秒以内で画面に反映。
- 主要レイアウト3種（配信中／待機／終了）の切替が即時。
- 障害時の手動復旧手順が`02_operation.md`に記載。

## 6. 想定構成（概要）
- **OBS**：シーンコレクション＋プロファイル（YouTube向け）
- **連携**：OBS WebSocket（外部コントローラ：Python/Node.js いずれか）
- **UI**：Stream Deck もしくはブラウザソースUI（ボタン）
- **コメント**：YouTube Live Chat API または専用表示ツールをブラウザソースで読込

## 7. 今後の成果物
- `01_design.md`：シーン・ソース命名規約、レイヤー構成、コメント表示方式
- `02_operation.md`：配信開始/終了手順、ボタン割当表、トラブル時の復旧
- `03_reference.md`：使用プラグイン、既知の制限、FAQ

## 8. リスクと対策（抜粋）
- **APIエラー**：コメント取得停止 → 画面側は最後のコメントを保持し、UIで再接続。
- **PC負荷**：録画＋配信でエンコード負荷上昇 → ハードウェアエンコード優先、解像度/ビットレートのプリセット用意。
- **手順ミス**：開始順序誤り → ワンボタン化とチェックリスト整備。
